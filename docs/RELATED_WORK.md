# Related work and contribution boundary

Literature reviewed 2026-10-27, before the pilot. Sources below are primary research, project documentation, or authors' own technical reports. This is a targeted search, not an exhaustive systematic review. Experimental results are reported separately; this review establishes the contribution boundary.

## Required starting points

**Madaan et al. (2024), _Quantifying Variance in Evaluation Benchmarks_.** [Paper, arXiv:2406.10229v1](https://arxiv.org/html/2406.10229v1). The authors study benchmark variance across checkpoints and model initializations, compare discrete and continuous metrics, and examine item analysis and item response theory. Their training-seed variation is distinct from repeatedly decoding one frozen checkpoint. Their analysis includes small public models and HumanEval, so neither “small models” nor “code evaluation variance” alone is novel. We replicate the general recommendation to quantify uncertainty, using frozen checkpoints and item-level outcomes; we do not claim to reproduce their training experiments.

**Evan Miller (2024), _Adding Error Bars to Evals: A Statistical Approach to Language Model Evaluations_.** [Paper, arXiv:2411.00640v1](https://arxiv.org/html/2411.00640v1); [Anthropic explanation, November 19](https://www.anthropic.com/research/statistical-approach-to-model-evals). Miller defines a question superpopulation, discusses dependence between questions, repeated generations, paired model differences, and power analysis. These foundations already cover the rationale for our CIs and minimum detectable differences. Our bootstrap win fractions are stability summaries, not posterior probabilities of model superiority. The separate sampling diagnostic is conditional on fixed items; inference beyond the benchmark requires assumptions about representative, independent items.

## Newer directly relevant work

**Sida Wang (2025), _Measuring all the noises of LLM Evals_.** [arXiv:2512.21326v1, December 24, 2025](https://arxiv.org/html/2512.21326v1). Some subsequent sources cite this as 2026; we identify the version we read explicitly. Wang separates prediction, data, and total noise using the law of total variance and applies paired analysis to all model pairs. This substantially covers the original project's proposed statistical decomposition. Our power projections subtract finite-repeat sampling variance from the observed variance of item means, with an explicit clipping warning. We claim no new variance decomposition or all-pairs method.

**Song, Wang, Li, and Lin (2025), _The Good, The Bad, and The Greedy: Evaluation of LLMs Should Not Ignore Non-Determinism_.** [NAACL paper and metadata](https://aclanthology.org/2025.naacl-long.211/). This compares decoding strategies and repeated outputs, including the utility of best-of-N sampling. It motivates reporting generation variability rather than treating one sampled response as a model's definitive ability. Greedy-versus-sampling performance is distinct from greedy sensitivity to serving batch configuration.

**Atıl et al. (2025), _Non-Determinism of “Deterministic” LLM System Settings in Hosted Environments_.** [Eval4NLP paper and metadata](https://aclanthology.org/2025.eval4nlp-1.12/). The study repeats ostensibly deterministic API evaluations and distinguishes raw-output agreement from parsed-answer agreement. We likewise report exact output disagreement separately from score disagreement. Our controlled, pinned, single-GPU experiment can manipulate batch configuration directly; provider-side changes in hosted APIs are outside our study.

**Thinking Machines Lab (2025), _Defeating Nondeterminism in LLM Inference_.** [Technical report](https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/). This explains how changes in batch shape and numerical reductions can change a request's output even when individual kernels are reproducible. It proposes batch-invariant computation. Our baseline/fix comparison is a replication of this mechanism's practical implications, not its discovery. We must test whether output differences reach the scorer and alter a ranking; an output change alone is insufficient evidence.

**Gond et al. (2026), _LLM-42: Enabling Determinism in LLM Inference with Verified Speculation_.** [arXiv:2601.17768](https://arxiv.org/abs/2601.17768). This proposes scheduling and verification to obtain deterministic decoding. It demonstrates that mitigation is an active systems research topic. Implementing that system is outside our budget; our mitigation arm uses a documented vLLM setting.

**Spencer Frei (2026), _Quantifying Pretraining Variance: Data, Initialization, and Floating Point Arithmetic_.** [Author's technical report, August 17](https://spencerfrei.github.io/blog/2026-08-17_pretraining_variance/). This separates initialization, training-data order and arithmetic-order changes in paired small-language-model training experiments. It reinforces the distinction between training-seed sensitivity and decoding a fixed checkpoint. We measure the latter and do not infer training variance from repeated inference.

**James Fiedler (2026), _Bootstrap Confidence Intervals for LLM Evaluation_.** [Author's engineering report, July 8](https://engineering.indeedblog.com/blog/2026/07/bootstrap-confidence-intervals-for-llm-evaluation/). This compares bootstrap strategies on repeated predictions, recommends resampling whole item clusters, and discusses the tradeoff between items and generations. It is particularly relevant to avoiding an extra inner bootstrap that can count finite-repeat variance twice. Our default therefore carries each item's full observed sample vector through a paired item bootstrap; a separate sampling bootstrap answers a conditional question.

## Implementation and benchmark sources

- [vLLM v0.32.0 batch invariance documentation](https://docs.vllm.ai/en/v0.32.0/features/batch_invariance/) and [pinned source environment definitions](https://github.com/vllm-project/vllm/blob/v0.32.0/vllm/envs.py): `VLLM_BATCH_INVARIANT=1` exists. Documentation lists NVIDIA compute capability >=8.0 and the Qwen, Llama, and Phi families. Documentation alone does not establish compatibility or throughput for a workload. Our approved pilot ultimately used NVIDIA A10; no L4 scientific result is claimed.
- [Official BFCL repository](https://github.com/ShishirPatil/gorilla/tree/main/berkeley-function-call-leaderboard): frozen single-turn AST subset, official prompting and checker. Our subset score is not the full BFCL leaderboard score.
- [Chen et al. (2021), _Evaluating Large Language Models Trained on Code_, arXiv:2107.03374](https://arxiv.org/abs/2107.03374): source for the unbiased pass@k estimator, `1 - C(n-c,k)/C(n,k)`, with `n >= k` and iid generations. This estimates at least one correct candidate, not a deployable selection method without an oracle.
- [Official EvalPlus repository](https://github.com/evalplus/evalplus): optional HumanEval+/MBPP+ execution and scoring. Code execution must remain on isolated CPU workers.
- [vLLM upstream issue #50440](https://github.com/vllm-project/vllm/issues/50440), reported July 2026: broadcasting one seeded parameter object across prompts can share sampling noise. We use explicit per-request parameters and distinct, nonoverlapping seed blocks; n child samples remain within each item's block. This is an implementation precaution, distinct from batch-invariant arithmetic.

## Approved narrower question

The user approved: **Do batch-sensitive greedy outputs change small-model BFCL rankings, and does vLLM batch invariance remove such changes at a throughput cost?** Retain the original CLI, six-model plan, and optional code benchmark.

The contribution is a practical, budget-constrained replication with reusable, inspectable per-item artifacts and analysis. Pair each default run with a batch-invariant run, hold prompts/checkpoints/scoring fixed, report both score and text changes, and compare warm throughput under matching batch configurations. Report a null result if no flips occur. Do not describe a six-model pilot or a population result when only two models and 100 items have been measured. Training seeds, prompt sensitivity, cross-GPU variation, and longitudinal provider drift remain outside scope.

Search terms included benchmark evaluation variance, prediction/data noise, seed sensitivity, deterministic greedy decoding, batch-invariant inference, and eval sample complexity, covering 2024–2026. Search date bounds all recency claims. Related work does not establish that our chosen model pairs are close in measured ability; that remains an empirical question.
